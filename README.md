## Open the program

On a new Windows PC, download the repository ZIP, extract it and double-click **Install Control Room.cmd**: it brings Node 24 and FFmpeg into the folder, links it to GitHub and makes a desktop shortcut (docs/INSTALL.md); **Update Control Room.cmd** takes new versions. Otherwise clone this repository, then on Windows double-click **Start Control Room.cmd**. It starts a hidden local server and opens the browser. Keep that checkout in place while running. To stop it, use **Stop Control Room.cmd**.

The app opens at http://127.0.0.1:3456. It is local to your computer. The launcher installs the locked packages (`npm ci`) on the first start of a fresh download and again when an update changes them; that start needs an internet connection. Planning requires no account setup or API key. Optional public YouTube lookup requires your own API key. Node.js 24 must be installed and available on PATH; this computer had Node 24.18.1 during development.

Alternatively, open a terminal in this directory and run:

```text
npm ci
npm start
```

Use Ctrl+C to stop a terminal-started server. A different local port can be supplied through PORT. The Windows launcher uses 3456.

## What works now

1. Create a channel family and choose one primary content locale plus any optional additional language channels. One-language families are valid; no language trio is mandatory.
2. Set the audience tier, countries, niche hypothesis, format, cadence, locales and budget.
3. Write an original draft in the family’s primary locale, record a hook/angle and attach evidence with source-rights notes.
4. Submit it for review and approve the exact script version when the required checks pass.
5. Prepare a saved, approximate six-scene planning scaffold and export the content as JSON.
6. Edit and revise safely: changes invalidate old approvals and storyboards; conflicting edits are rejected instead of silently overwriting.
7. Archive/restore families without deleting work, reopen saved data and inspect the build tracker.
8. Save a YouTube Data API key with Windows account protection, then look up a public channel by handle, ID or URL. See [YouTube setup](docs/YOUTUBE-SETUP.md). The connector has fixture coverage; verification with your live project remains pending.
9. Add, edit, test and delete named connector slots. Each provider has its own small connection test (YouTube, Google OAuth client, OpenAI, ElevenLabs, Fish Audio, Claude, ChatGPT through Codex, NexLev, Pexels, Pixabay, Wikimedia, Reddit, Freesound, Jamendo); MCP slots are setup records only. See [Connector guide](docs/CONNECTORS.md).
10. Configure Claude in Connections, using the existing local Claude Code or API direction, and test that selected connection explicitly. Queue a bounded script job and review its immutable candidate. The writer keeps family token limits, originality checks and human approval. Live provider verification is still required; installed code alone is not a connection.
11. Save family-scoped, dated evidence with explicit permission and analysis labels, then manually prepare zero to three immutable daily topic briefs. Briefs retain source snapshots, confidence, uncertainty, duplicate checks, token usage and deliberate retry history. They are review-only and never create drafts or publishing work. See [Research briefs](docs/RESEARCH-BRIEFS.md).
12. Use the professional per-family Production Panel and complete Voice Room to record narrator rights, delivery direction, pronunciation revisions and character budgets; generate explicitly admitted primary-locale auditions through a tested OpenAI or ElevenLabs connector; inspect real FFmpeg audio evidence; and approve or revoke one exact narration handoff. See [Voice Room](docs/VOICE-ROOM.md).
13. Add 3-10 competitor channels to each family (@handle, channel ID or channel link). The Competitors page studies them (item 15).
14. Use Room 03, the Style Library & Assignment Room, to review five launch editing styles (or your own custom/derived styles), approve exact revisions, assign one default style per family, add deliberate per-channel overrides and approve manual-only fallbacks. Every change is a new immutable revision with a visible diff and a decision trail. See [Style Room](docs/STYLE-ROOM.md).
15. Use the **Competitors** page to record your own observations per competitor, tick what to keep from each link (voice-over, narration, editing, thumbnails, visuals) to build a blend recipe, run an explicit NexLev/YouTube scan against reserved data caps, ask Claude for a technique blueprint that must pass the 30% reference / 70% original rule and a copy guard, and approve it. An approved blueprint feeds Claude script guidance, can prefill a narrator profile and can create a new style draft; each still needs your review. YouTube data about other channels is display-only and deleted after 30 days. See [Competitor Intelligence](docs/COMPETITOR-INTELLIGENCE.md).
16. Use the **Niche Factory** to save your own niche ideas, run NexLev discovery (niche overview, similar channels, keyword search, analytics estimates), have Claude rate each idea on the blueprint rubric (score computed by the program; failed hard filters mean "do not produce"), then shortlist, reject or approve, and create a new family from an approved niche. See [Niche Factory](docs/NICHE-FACTORY.md).
17. Use Room 04, the **Scene & Visual Room**, to turn an approved script, its approved narration and the family style into a revisioned scene plan (free narration split or Claude scene director), edit scenes and shots with stable IDs, find visuals from Pexels and Pixabay (24-hour cached searches, licensed downloads with checksums and ffprobe evidence) or generate AI images with OpenAI within a monthly budget, then approve the whole board with rights and AI-disclosure decisions. See [Scene Room](docs/SCENE-ROOM.md).
18. In Room 05 (Editing Room), check and pin your FFmpeg build, then render the **assembly preview**: a 360p proxy of the approved board on the approved narration with Ken Burns stills, held or trimmed clips and the style's transitions. Every proxy gets length, frame, audio, black-frame and frozen-picture checks, a contact sheet and a render manifest with checksums and commands; you record the style-proof verdict. See [Render proof](docs/RENDER-PROOF.md).

19. Open the **Skills** page to read the program's operating knowledge: 349 skills taken from your main-brain documents (Precision OS, the YT Empire Builders library and the CB YT AI Mastery bundle), from the editing research and from two YouTube repositories (youtube-agent-skill and HyperFrames), each written in our own words. They all arrive as **drafts** and change nothing until you approve that exact revision. Channel and niche profiles are marked "pin to a family": they only reach a family you pin them to. You can add your own skills, import or export a pack, pin or block a skill for one family, record LOCKED/ACTIVE/OPEN/REJECTED decisions per family, and review the lessons the program raises from its own blocked scripts, rejected scene plans and style proofs. A lesson you approve becomes another draft, never a live rule. See [Skills Engine](docs/SKILLS-ENGINE.md).
20. In **Production → Room 05 · Editing**, press **Draft the edit**. The editing brain measures the pauses in the narration and cuts, times and moves every shot with a written reason, proposes graphics (numbers, quotes, dates, your title card at a turn, and animated charts, timelines, lists, comparisons and process diagrams drawn from the script's own data), and the critic lists anything boring, lazy or amateur with a fix. Change any decision, redo one scene, undo, then **Render this edit** and record the style-proof verdict. Run the FFmpeg readiness check again once after updating. See [Editing Room](docs/EDITING-ROOM.md).
21. **Captions and YouTube craft (0.14).** Every new edit carries captions timed on the narration's pauses: they are burned into the render (bottom band on 16:9, above the Shorts buttons on 9:16), can be switched off as an edit change, and download as an SRT file for YouTube. Under the edit you also get draft **YouTube chapters**, up to five **Shorts** hiding inside a long video, and a reader for a **YouTube Studio retention export** that names the hook leak, the cliffs (with what the narration said) and one fix. In the Content studio every draft shows a **Craft check**: a hook score with its weakest point, a title check and a thumbnail-text pairing check. In a family's settings you can add its **writing voice** (who one video talks to, words it never uses, its own phrases, claims it refuses); Claude writes in it and blocks never-used words. Competitor scans now show each video as a multiple of its channel's median and the hook formula its title uses.

22. In **Production → Room 07 · Audio**, choose original levels or normalized narration, save a new edit revision and render its audio/video preview. Inspect the encoded audio checks, download the WAV and record a named listening review. See [Audio Room](docs/AUDIO-ROOM.md). Music and effects: item 30.
23. In **Production → Room 08 · Review & QC**, open the newest render. You get one issue list in time order (render checks on the real file, the editor's critique, every caption), each with a button that opens where it is fixed. The narration is aligned sentence by sentence with its captions, clips, graphics and a frame, next to timestamped contact sheets of the whole video and its hook. Then record the style-proof verdict here. See [Review & QC](docs/REVIEW-QC.md).
24. **Claude checks every frame first (0.17).** In Room 08 press **Ask Claude to scan every frame**, or switch on *scan every new render* for the family. Claude reads a frame from every shot, graphic and the hook beside what is said there and flags only real problems, each with its frame and a fix button. You then check just those moments and record the verdict.
25. **Any length (0.17).** Set **Target length (minutes)** on a draft: 1 to 180 minutes. The script, scene planning, narration, edit, render and review all scale with it. See [Video length](docs/VIDEO-LENGTH.md).
26. In **Production → Room 09 · Packaging**, start a package from the script or ask Claude for one: 5 titles, 3 thumbnails drawn from your approved visuals (judge them at phone size), a description with chapters, the AI note and visual credits, tags and the synthetic-content choice. Every figure must come from the script. Approve it for the video you approved in Room 08 and download it for YouTube Studio. See [Packaging Room](docs/PACKAGING-ROOM.md).
27. **Drawn videos (0.19).** Assign the Stickman Sketch Explainer, Hand-drawn Canvas or Motion Graphics style. When Claude plans the scenes it draws each shot in words (stick figures, props, labels, arrows, bubbles); in Room 04 press **Draw all scenes** and the program draws every shot itself, free and local, as a clip the editing brain edits like footage. See [Drawn scenes](docs/DRAWN-SCENES.md).
28. **Engines that work together (0.20).** Stick-figure videos now have recurring characters with looks, expressions and gestures, built sets, props that move, a motion-graphics layer and drawings that arrive on the narrator's words; hand-drawn and motion-graphics shots join documentaries as cutaways. Each style says which engines may join it and which never do. Built-in styles you have not changed get the newest version as a draft in Room 03. See [Drawn scenes](docs/DRAWN-SCENES.md).
29. **Voice direction (0.22).** In the Voice Room press **Direct the voice**: Claude marks how every sentence is spoken (emotion, energy, pace, pauses, stressed words) so the story rises and falls. Open the direction to change any line. Auditions then perform it (ElevenLabs v3/v4 voices read emotion tags), and the scene planner matches faces and moods to it. See [Voice direction](docs/VOICE-DIRECTION.md).
30. **Music and sound effects (0.23, sound library since 0.60).** Fill the **Sound library** with music and effects you downloaded (Pixabay, YouTube Audio Library: import the folder) or find CC0 and CC BY sounds on Freesound and Jamendo from inside the program (0.61; their API terms need your confirmation for commercial use). **Ask Claude to score the video** (or make the free score): cues that follow the story, picked from the library by mood, energy and length and changeable per cue and per effect. Switch music and effects on in **Change audio settings** and render: the music is ducked under the voice and the effects land on the drawn moments. ElevenLabs music generation is no longer used. See [Audio Room](docs/AUDIO-ROOM.md).

The early six-scene storyboard remains a planning scaffold; the approved Scene Board and Editing Room produce real local proxy renders. AI calls and narration/visual generation are explicit actions with their existing budget and review gates. Language editions (Room 06), final masters (Room 10) and private upload, scheduling and the locked autopilot (Room 11) are built and tested with test doubles; none has run against a real channel or provider yet.

## Where your work is saved

`data/control-room.sqlite` contains your families, drafts, evidence, immutable briefs/candidates, voice profiles, audition provenance, cost ledgers, approvals, jobs and activity. Generated narration is stored beneath `data/voice-artifacts/`; immutable render outputs, including finished narration WAVs, live beneath `data/renders/`. SQLite may keep `-wal` and `-shm` companion files while running. Do not remove these while the app is open. Stop the app before copying the whole data directory for a manual backup.

The exported planning JSON contains the selected draft and its source references; it never includes API keys. Named slot keys are encrypted for your Windows account in the SQLite connectors table. Existing v0.2 keys remain in `data/youtube-key.dpapi`. Other machines/accounts may require key re-entry. Removing a key or slot affects the current local copy; provider revocation and old backups are separate.

## Current architecture

`server.js` handles loopback HTTP, guarded writes and saved queues. `store.js` validates inputs, approvals and transactional SQLite changes. `ai.js` provides the Claude boundary and `writer.js` owns script candidates; research and intelligence are separate room services. `voice.js`, `style.js` and `scene-room.js` manage immutable approved inputs. The pure `editing-brain.js` proposes edits; `editing-room.js` stores validated revisions; `render-room.js` executes pinned local tools through `render.js`. `audio.js` supplies pure narration settings/filter/QC helpers. `public/` renders the room interfaces without a frontend framework. One local process owns SQLite.

## Troubleshooting

- **Node 24 required:** install a supported Node 24 runtime, then restart the launcher.
- **Packages could not be installed:** the first start of a fresh download (and the first start after an update that changes package-lock.json) runs `npm ci`; connect to the internet and start again.
- **Port already used:** the launcher reopens an existing matching Control Room instance. If another app owns port 3456, it stops with an explanation instead of terminating that app.
- **Connection refused:** rerun the launcher. Check data/server-error.log after a launcher-started failure.
- **Item changed in another tab:** close the edit dialog, refresh the page, reopen the latest record and reapply your changes.
- **Draft cannot enter review:** the draft card lists missing requirements. Source permissions are your explicit review, not a claim of automatic legal verification.
- **Generation is budget blocked:** increase the family's explicit monthly or per-job token ceiling, or wait for its next local calendar month. Dollar budget and token ceilings are separate fields.
- **FFmpeg not installed:** planning still works, but Voice Room auditions remain blocked because returned audio cannot pass the mandatory local validation gate.

The tests reduce known failure risks; they cannot establish that a program has no bugs. Live provider and channel behavior will need separate verification as those stages are implemented.
